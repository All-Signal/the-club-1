# 🏛️ THE TRIUMVIRATE // MERGE & CLEARANCE SPECIFICATION

In accordance with founding protocols, individual maintainer identities are strictly classified to maintain sovereign operational autonomy. Merge authority over **THE CLUB 1** repository and Obsidian Vault is strictly restricted to three designated council nodes:

## 🛡️ Enforced Controls

### 1. Internal Codeowners Security
No Pull Request can bypass codeowner review. The repository designates codeowner authority exclusively to verified Tier-0 Council signatures.

### 2. GitHub Actions CI (`merge-guard.yml`)
- Any direct push event to the `main` branch verifies that the actor has Tier-0 clearance. Unauthorized pushes immediately fail and are flagged.
- Pull request runs verify note integrity, check for malformed wikilinks, and ensure proper metadata frontmatter without leaking private maintainer data.

### 3. Branch Protection Protocols
Branch protection on `main` requires:
- Codeowner approval prior to merging.
- Dismissal of stale reviews upon new commits.
- Strict restriction of push access to authorized accounts.

## 📜 Pull Request Lifecycle for Outside Contributors
1. **Branching:** Contributors fork or branch under `persona/*`, `vertical/*`, `playbook/*`, or `feat/*`.
2. **Standardization:** Notes must follow templates defined in `Templates/` and incorporate valid Obsidian wikilinks.
3. **The Crucible Check:** PR review conducted by a Tier-0 Council member.
4. **Merge Execution:** Merged into `main` exclusively upon Council approval.
